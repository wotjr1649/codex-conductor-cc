# Post-v0.3 handoff

v0.3 is merged. This is the entry point for whatever comes next: what is measured, what is still
open and why, and the order that follows from both.

Read `docs/superpowers/specs/2026-08-14-v0.3-hardening-program-design.md` first — it is the record
of the program, including several corrections to its own earlier claims. This file does not repeat
it.

## Where the repository stands

Every code defect in the v0.3 catalog is fixed and on `main` (34 commits, PRs #7 and #8). Three
review passes ran over it: a cross-provider review of the three riskiest job-reliability changes
(8 findings), a full-branch review (27), and a review of the baseline-identity work (7, one of them
critical). All were applied or declined with a recorded reason.

The continuity gate is healthy and stricter than it was: `PORTABILITY_BASE` is the reviewed v0.3
head, and the two checks that encoded one-time transformations became byte identity. `V1` and `V2`
are resolved — `npm run validate:p3` passes and all five baseline suites have a CI trigger, 77
assertions that previously ran nowhere. CI covers four platforms; the POSIX legs run the unit suite
for the first time.

Versions are `0.2.0` across all six manifests. The release identity is asserted as a relation now,
not a literal, so the next bump will not break the baselines the way v0.2's did.

## The measured fact that should decide the next order

```
contract snapshots pinned:  0.145.0, 0.146.0
codex-cli installed here:   0.147.0
```

The design document says protocol drift outranks any single defect in the catalog, and in the same
paragraph that **nothing reports drift today**. There is now drift, at least one release of it.
What is not known is whether `0.147.0` changed anything this plugin depends on — that is a question
about the outside world, and it has to be answered from a current source rather than from recall.

Until it is answered, work on features is speculative: P6 designs against a protocol nobody has
confirmed is still the protocol.

## Debts worth folding into any session

Each is small and pays for itself immediately.

- **Tests leave broker processes behind.** A stale broker poisons every later run in the same
  workspace for `IDLE_SHUTDOWN_MS` — thirty minutes. This cost three wrong diagnoses in one
  session: a 61-second regression that survived reverting every source file, because it was not in
  any source file.
- **Registry digests are a mix of CRLF and canonical.** Which one a file matches decides which
  checkout it passes on. `findCrLfDigestPaths` absorbs this for the continuation, but suites that
  call the raw validator do not get that. Canonical everywhere would remove the dependency.
- **The POSIX CI leg names its test files individually.** A new test does not join it by being
  written. `platform-policy.test.mjs` was excluded that way, which is why a win32-only assertion in
  it survived a change that made the suite run on three more platforms.

## Suggested order

1. **Measure the drift.** Everything else is downstream of whether the protocol moved.
2. **Unblock the two decisions.** `#499`/`#640` and `#382` are both stalled on information that
   exists publicly. Fetch it, then decide — the decisions themselves are the maintainer's.
3. **Check upstream.** What `openai/codex-plugin-cc` has done since v0.2 determines what an
   absorption pipeline has to handle.
4. **Then brainstorm tooling.** Diverging before the three inputs above are in hand reinvents
   whatever upstream already shipped.

## What this session learned about verifying its own work

These are not general lessons; they are specific traps this repository sets, and every one of them
was walked into.

**A gate that exits 0 has told you nothing about what it refuses.** The identity-refresh branch
passed all three validators, a merge simulation, and CI, and was reported as safe — then a review
found that a prefix-matching regex let a `pull_request_target` trigger through the very check a
newly added CI step existed to run. Verify a gate by mutating what it should reject, not by
confirming it accepts what is already there.

**A clone made with `core.autocrlf=false` reproduces the POSIX legs only.** The Windows runner
checks out through Git for Windows' default, which is CRLF, so Windows-only suites must be measured
in an `autocrlf=true` clone. Two suites read as failing for a full round of analysis because of
this.

**A probe script written into the repository is itself a gate violation.** `P6E_SCOPE` fires on it,
so the probe "passes" for a reason that has nothing to do with what it was testing. Run probes with
the repository as cwd and the script outside it.

**Four separate measurements in this session were wrong because the probe was handed different
inputs than the code under test uses** — the wrong profile registry twice, the wrong validator
once, and a stale workspace once. When a measurement contradicts a passing test, suspect the
measurement first: call the same entry point the test calls, with the same arguments.
