# Codex Conductor v0.2 Release Notes Design

**Status:** Approved for the personal public fork.

## Outcome

Prepare one documentation-only pull request that makes the installed plugin's changelog describe
the already-merged v0.2.0 portability release before any tag or GitHub Release is created.

## Scope

- Start from exact personal-fork `main` commit
  `51aa48034e655aacce23938df792bc6da65b049f` on branch
  `codex/v0.2-release-notes`.
- Add one `0.2.0` entry to `plugins/codex/CHANGELOG.md` using only claims already supported by the
  root `CHANGELOG.md`, README, portability design, and successful PR #4 evidence.
- Retain the existing `0.1.0` and inherited `1.0.0` entries unchanged.
- Include this design record in the documentation pull request.

Do not change runtime code, tests, workflows, package or marketplace versions, the root changelog,
README, release assets, or support policy. Do not write upstream, publish to npm, submit to a central
marketplace, create a tag or release, or install anything globally.

## Release-note content

The plugin changelog entry will state the exact supported tuples:

- Windows x64
- Linux x64
- macOS x64
- macOS arm64

It will summarize the portable private runtime paths, authenticated POSIX control channels,
owned-process shutdown, and four-platform CI gate without adding implementation claims beyond the
merged v0.2.0 record. Unsupported tuples remain outside this documentation change.

## Validation and pull request

Before publication, review the exact diff and confirm version metadata and portability continuity
with the existing repository validators. Create at most one draft pull request from the personal
fork branch to personal-fork `main`, then observe only its naturally created CI and review state.

Stop without retrying or widening scope if the base commit, remote target, branch state, validation,
CI, or review state differs from the expected clean path. Ready conversion, merge, tagging, and the
v0.2.0 GitHub Release require later explicit approval.
